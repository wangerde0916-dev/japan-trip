# 日本冬季 14 天随身手帖

一个手机优先的静态网页 App，包含行程、美食与咖啡打卡、多币种预算记账、出行清单、日语短句和紧急信息。没有框架、CDN、在线字体或运行时依赖。支持穷游、舒适、豪华三个版本，来自随包提供的三个 JSON；`route-map.svg` 原样保留。

## 本地查看

### 最简单：双击打开

直接双击本目录里的 `index.html`。浏览器通过 `data.js` 读取行程，不需要联网、安装 Node 或启动服务器。六个页面、路线图和记账均可在本地使用；地图按钮需要网络并会打开外部 Google 地图。

勾选、支出和汇率保存在当前浏览器的本地存储里。不同浏览器、浏览器配置、`file://` 与 HTTP 地址之间不会自动同步。移动文件位置或清理浏览器数据，也可能使原来的记录不可见。浏览器限制本地存储时，操作仍可继续，但记录可能仅在当前页面保留。建议定期从预算页面导出支出 CSV。

`file://` 模式不注册 service worker，不能获得 PWA 的安装和缓存管理功能。日语朗读需要浏览器支持语音合成，并且是否可离线朗读取决于设备有没有安装日语语音。

### 可选：通过本地服务器使用 PWA

当前电脑已有 Node，可在本目录打开终端运行：

```powershell
node scripts/serve.mjs
```

然后在浏览器打开 [本地预览](http://127.0.0.1:4173/)。按 `Ctrl+C` 停止服务器。可选第二个参数更换端口，例如 `node scripts/serve.mjs 8000`。

如果电脑已安装 Python 3，也可在本目录运行：

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Windows 若使用 Python Launcher，也可运行 `py -3 -m http.server 8000 --bind 127.0.0.1`。在浏览器打开 [http://localhost:8000/](http://localhost:8000/)。服务器只是方便预览，不是 App 的依赖。

首次联网访问后，等待页面加载完成并让 service worker 安装成功，再刷新一次。浏览器会缓存页面、脚本、样式、路线图、行程数据、清单配置和图标；之后可离线打开。支持安装的浏览器通常在地址栏或菜单里提供“安装应用”/“添加到主屏幕”，iPhone Safari 可从分享菜单选择“添加到主屏幕”。具体入口由浏览器决定。

Service worker 需要安全环境：`http://localhost`（或本机回环地址）或者 HTTPS。手机访问电脑的普通局域网 HTTP 地址通常不能注册 service worker；若要在手机上安装并离线使用，建议部署到 GitHub Pages 的 HTTPS 地址。Google 地图属于外部服务，不会被离线缓存。

## 更新行程

1. 穷游版来自 `trip-data.json`，舒适版来自 `trip-data-plus.json`，豪华版来自 `trip-data-lux.json`。本次按 V3 更新包覆盖，三个文件与包内原文完全一致；数据疑问记在 `NOTES.md`。以后只在确认内容调整后编辑对应 JSON。
2. 安装 Node 后运行以下命令，生成新的 `data.js`：

   ```powershell
   node scripts/build-data.mjs
   ```

   脚本只使用 Node 标准库，不需要 `npm install`。它会先检查三个 JSON 的语法，再把原始文本分别包成 `window.TRIP_DATA = …;`、`window.TRIP_DATA_PLUS = …;`、`window.TRIP_DATA_LUX = …;`，一起写进 `data.js`，不会重新编排、补写或改动行程内容。脚本按自身路径定位项目，所以从任意目录调用都可运行。
3. 刷新页面。不要手动编辑 `data.js`，再次生成会覆盖它。
4. 对已部署的 PWA，同时递增 `sw.js` 中 `CACHE_NAME` 的版本（本次从 `v4` 改为 `v5`），把相关文件一起上传。新 service worker 只有在全部文件缓存成功后才会激活；完成更新后再刷新页面。仅修改数据而不递增缓存版本，旧安装可能继续使用先前缓存。

本地勾选与记账不会随行程文件上传；在信息页面重置需要确认，只影响这个 App 在当前浏览器的本地记录。修改行程结构后，建议先导出支出 CSV，并核对已有勾选是否仍对应正确项目。

## 三个版本与本地记录

标题旁的「穷游 / 舒适 / 豪华」按钮切换版本，默认穷游，下次打开记住上次选择。六个页面跟随切换；当前日期、页面和未提交的记账草稿会保留。`tier: plus` 店铺带金色「升级」标签，`tier: lux` 带紫色「豪华」标签，美食列表保持数据顺序。

原有 `japan-winter-trip:v1` 存储入口保持不变。无版本前缀的旧勾选自动归入 `budget:`；已有 `budget:`、`plus:` 原样保留，豪华版使用 `lux:`。三版勾选独立，重复打开不会重复加前缀。支出数组和汇率共用，不同名称的住宿预算归在同一住宿统计下，已保存的账单分类文字不改动。重置会清除三个版本的勾选以及共享账本、汇率和显示币种设置，需要确认。

手机更新时使用原来的网址和浏览器，联网打开、待离线资源更新完成后再刷新。无需清除浏览器数据或重新安装，清除网站数据会丢失仅存在本机的记录。

## 咖啡、多币种与付款人

- 美食页保留城市筛选，新增早餐、咖啡、奶茶 / 抹茶、蛋糕甜品、下午茶分类。选择具体分类只显示相应咖啡甜品；选择「全部」恢复打卡、正餐和咖啡分组。行程页「今天附近吃什么」在正餐后列出当天城市的咖啡甜品，展示开门时间，休息店铺标红并排到该列表末尾。
- 预算页可选择「日元 + 美元」「日元 + 人民币」「日元 + 美元 + 人民币」，默认三种。日元记账金额不变，换算价用 `US$`、`CN¥` 区分。人民币与美元汇率、显示偏好在三版本间共用，并保存到本地。
- 新用户的汇率默认值来自 `meta.currencyRates`（1 美元 = 157 日元，1 元人民币 = 23.2 日元；参考日期 2026-11-16）。已有用户的美元汇率优先保留。两项汇率都可手动修改，不自动联网取价。
- 每笔支出可选填「谁付的」。未填写的旧账单仍保留并计入「未填写」汇总；其余按输入姓名汇总垫付金额，不自动计算分摊。CSV 保留原有列并追加付款人、人民币约数及人民币汇率；换算使用导出时当前设置。

## 部署到 GitHub Pages

1. 创建 GitHub 仓库，把本目录所有交付文件按原有目录结构上传（`index.html` 应处于发布目录根部）。上传 `data.js`，不需要在 GitHub 执行构建。
2. 进入仓库 **Settings → Pages**，选择 **Deploy from a branch**，选择已上传文件的分支及根目录 `/ (root)`，保存。
3. 等待发布完成，打开 GitHub 提供的 HTTPS 地址。所有资源路径都是相对路径，也支持 `https://用户名.github.io/仓库名/` 这样的项目子路径。
4. 首次在线打开并缓存后，刷新并尝试离线访问。后续修改按上面的“更新行程”同时上传，并递增缓存版本。

不要把浏览器中的个人记账当成云端备份。这个 App 没有账户、服务器数据库或跨设备同步。

## 文件说明

- `index.html`、`styles.css`、`app.js`：页面、样式和交互。
- `trip-data.json`、`trip-data-plus.json`、`trip-data-lux.json`、`data.js`：三个版本的原始数据及脚本生成的浏览器数据文件。
- `route-map.svg`：随包提供的路线图，保持原样。
- `manifest.json`、`sw.js`、`icons/`：PWA 配置、离线缓存及本地图标。
- `scripts/build-data.mjs`：无需依赖的数据生成脚本。
- `scripts/serve.mjs`：无需依赖的本机 HTTP 预览服务器。
- `qa/preview-mobile.jpg`：375px 手机视口的实际界面截图。
- `scripts/check.mjs`：运行 `node scripts/check.mjs` 检查数据等价、日期定位、预算、休息排序、状态恢复、记账与 CSV 等逻辑；全部通过时返回退出码 0，有失败则返回 1。该脚本使用 Node 内的最小 DOM 模拟，不能替代实际浏览器的布局、弹窗、语音、PWA 和离线验证。
- `NOTES.md`：数据疑问、自检记录及已知限制。

日语“出示模式”会显示大字；浏览器不允许真正全屏时仍可以在页面内使用。紧急电话链接需要设备支持拨号。行程中的价格、评分与营业说明按原始数据展示，标注需核实的项目请按原始说明在出发前确认。
